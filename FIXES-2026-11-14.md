# MoviesZoneFlix patch notes — 2026-11-14

## Force Subscribe / peer resolution

- FSub chat lookup and membership checks now call Telegram Bot API `getChat` and `getChatMember` first, with Pyrogram `resolve_peer` fallback.
- Public join URLs are built from the chat username. Private invite links are created through `createChatInviteLink`; the bot needs invite-user permission.
- Added clearer FSub diagnostics when a destination cannot be resolved or no invite URL can be created.
- Applied the same Bot API-first resolution to `/panel fsub add` and group `/fsub` configuration.
- Normalized positive compact channel IDs to `-100…` while preserving negative legacy/basic-group IDs.

## Telegram peer-resolution and index-cleanup patch

- Fixed `utils.py` to import the existing official Bot API request helper. Previously,
  the helper calls raised `NameError`, were swallowed, and silently fell back to
  Pyrogram's peer cache; this explains why FSub still logged `Peer id invalid`.
- FSub destination lookup and membership checks now use the official Bot API directly,
  without attempting Pyrogram peer resolution.
- Auto-post send/edit operations now use Bot API `sendMessage` / `editMessageText`.
- Startup now enumerates log, environment/panel FSub, managed/index, request, support,
  delete, and auto-post destinations. It logs `getChat`/bot membership/send access
  and sends then immediately deletes a temporary probe message.
- Newly indexed documents record their source chat/message IDs. A deleted-message
  handler removes matching records across all configured file database nodes.
- Startup probe messages are deleted immediately. Telegram may still reject deletion
  if the bot lacks delete-message rights; that exact failure is logged.


## Auto-post resolution and metadata improvements
- Detects numeric resolution labels from 144p through 4320p, including every integer value from 480p through 600p (for example 480p, 500p, 540p, 576p, 599p, 600p).
- A standalone resolution in the Telegram caption metadata takes priority over a conflicting resolution token in the filename (for example filename 720p with metadata line 540p is grouped as 540p).
- Keeps separate resolution variants in the aggregation set so a 240p + 540p + 720p release set reaches the default three-quality trigger.
- Extracts and publishes duration metadata such as `2h 13m 56s`; language detection and merge behavior are retained.

## Native Bot API destination validation and deleted-index cleanup

- Startup validation now includes `CHANNELS`, `FILE_STORE_CHANNEL`, `DELETE_CHANNELS`, `LOG_CHANNEL`, `AUTH_CHANNEL`, `REQST_CHANNEL`, `INDEX_REQ_CHANNEL`, `SUPPORT_CHAT_ID`, database-managed index channels, saved panel FSub chats (even while the FSub toggle is off), and the auto-post destination.
- Each configured numeric destination is resolved and checked with Telegram's official Bot API. Startup sends a silent temporary probe message and immediately attempts `deleteMessage`; it logs the chat title, configured roles, bot membership status, and deletion outcome. This avoids Pyrogram's local peer/access-hash cache for these checks.
- Global FSub membership and join-link resolution use the official Bot API. Auto-post edit/send operations use Bot API `editMessageText` / `sendMessage` rather than Pyrogram `send_message`.
- Deleted source messages are removed from file-index records using stored `source_refs`. A file record is retained if another source message still references that same file; it is deleted once no source references remain. The existing `/delete` channel path also removes indexed files.


### Placeholder channel ID guard
- The documented sample ID `-1001234567890` is now ignored in environment file-index, file-store, delete-index, and database-managed channel normalization.
- `.env.example` now leaves `CHANNELS` empty instead of suggesting the placeholder as a real channel.
- This prevents the sample ID from triggering startup access failures or being treated as a managed index channel.
